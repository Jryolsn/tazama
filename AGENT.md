# AGENT.md

Context for AI coding agents (Claude Code, Cursor, Copilot and others) and for anyone
picking up the work by hand. Read this first, then `STATUS.md`, then the ticket you are
working on in `dev-tickets/`.

## What this is
Tazama: a Flutter launcher for Android TV / Google TV (GPL-3), forked from Arc Launcher
(which builds on LTvLauncher and FLauncher; credits in README and NOTICE).
Targets Chromecast with Google TV (HD "boreal" and 4K "sabrina"), armeabi-v7a.

Two apps live in this repository:

| App | Path | Stack | Application id |
| --- | --- | --- | --- |
| Tazama (TV launcher) | everything except `camera-app/` | Flutter + Java (Android) | `com.jryolsn.tazama` |
| Tazama Link (phone) | `camera-app/` | plain Gradle, Java | see `camera-app/app/build.gradle` |

## Commands
Flutter version is pinned in `.fvmrc` (3.41.9). With [FVM](https://fvm.app/) prefix commands
with `fvm` (`.vscode/settings.json` points the Dart extension at `.fvm/versions/3.41.9`).

```sh
fvm install                                              # once, installs the pinned Flutter
fvm flutter pub get
fvm flutter analyze
fvm flutter test
fvm dart run build_runner build --delete-conflicting-outputs   # after changing drift tables or @GenerateMocks
fvm flutter build apk --release --flavor github --target-platform android-arm   # TV APK, same flavor as CI
fvm flutter run --flavor github -d <adb serial>          # run on a connected TV

cd camera-app && gradle assembleRelease                  # Tazama Link (Gradle 8.13, JDK 17)
```

### Local development loop
The dev target is a physical Google TV over Wi-Fi adb (real remote, real performance).

```sh
cp .devrc.example .devrc     # once, then set TV_IP (gitignored)
./dev.sh                     # connects adb, runs the debug build with hot reload (r = reload, R = restart)
tools/dev/screenshot.sh      # saves .screenshots/tv.png from the dev TV
```
- The debug build is `com.jryolsn.tazama.debug` and installs next to the release app. Accessibility
  service and default-home must be enabled once for the debug app on the dev TV.
- Without `TV_IP`, scripts use a running emulator (`emulator-5554`, AVD `android_tv_arm64`). Fallback only:
  it has no real remote and its performance says nothing about the Chromecast.
- Shell scripts share device handling in `tools/dev/env.sh`. Use them instead of raw `adb`/`flutter run`
  so the target is always the one in `.devrc`.

### Verifying UI changes (agents)
1. Run `fvm flutter analyze` and `fvm flutter test`.
2. If the user has `./dev.sh` running, a saved edit hot reloads on the TV. Run `tools/dev/screenshot.sh`
   and read the PNG to check the result visually. Do not start `./dev.sh` yourself (it is interactive).
3. D-pad focus and key behaviour still need the user on the remote (see Rules).
4. If you could not build or run locally, say so instead of claiming the change works.

## CI and releases
- Every push to any branch runs `build-apk.yml`, except pushes that touch only `**.md`,
  `LICENSE`, `NOTICE` or `tools/**` (docs-only changes do not build).
- Feature branches build only the app they touch (`camera-app/` = Tazama Link, the rest = TV app).
  `dev` and `main` always build both, so every release carries both APKs.
- `dev` -> pre-release `v1.3.N-dev` (test TV), `main` -> release (main TV). TVs and phones
  update through Obtainium pointed at `Jryolsn/tazama`.
- APKs are signed with `android/app/sideload.keystore` so updates install over each other.
- PR titles are checked by `lint-pr-title.yml` (Conventional Commits, see CONTRIBUTING.md).
- Remote `upstream` = meddouribadis/arclauncher for cherry-picking fixes.

## Workflow
- Work happens both in the Claude app (cloud sessions) and locally (IDE, Claude Code, by hand).
  The repository is the shared memory: anything the next session needs goes in `STATUS.md` or
  the ticket's `PLAN.md`, never only in a chat.
- Branch from `dev`, open a PR to `dev`. `main` is only updated from `dev` for a release.
- Starting work: read `STATUS.md`, then `dev-tickets/INDEX.md` and the ticket's `PLAN.md`.
  Ending work: update the ticket's `## ▶` section, `INDEX.md`, and `STATUS.md` if a feature landed.

## Rules
- User-visible text in English. Commits, PRs and code comments in English; comments short and
  only where something non-obvious needs noting. Ticket plans may be in Swedish (see `dev-tickets/PROJECT.md`).
- No AI attribution anywhere (no Co-authored-by, "Generated with", session links).
- No personal data (names, emails, home IPs, device serials) in code, commits or docs.
- Keep upstream copyright headers and LICENSE; note changes in NOTICE.
- Key and accessibility features cannot be tested with `adb input keyevent`; test on a TV with the remote.
- Design for D-pad focus at the real TV canvas (960x540 dp, 48 dp side margins).
- The dev TV is the one in `.devrc`. Never install to, or run adb against, the main TV without being told.
